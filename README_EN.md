# DLSS5-Swapper-Plus

> English | [简体中文](README.md)

A Windows desktop tool for managing DLSS 5 (neural rendering) game plugins: it scans your locally installed games, installs or replaces DLSS5 runtimes, RenoDX and OptiScaler components in one click, and provides an in-game ImGui overlay control panel.

## Origin & Acknowledgements

## 1. Development & Build

### 1. Prerequisites

- **You must use an elevated (Administrator) PowerShell**. The workspace may contain directories running at a lowered integrity level (Low IL); a non-elevated terminal can cause hard-to-diagnose failures such as `AccessDenied` when compiling with zig, or Electron crashing on launch (`0xC0000005`).
- Node.js ≥ 24 (verified on Node 26), pnpm ≥ 12.
- **DLSS SDK distribution (manual step)**: `nvngx_dlssnr.dll` and friends are restricted by the NVIDIA license and are not downloaded with the build — you must supply them locally. Place the DLSS distribution contents (DLSS5 neural rendering + DLSS SR/RR/FG + the **Streamline runtime**, not just DLSS5) **flat** into `vendor\dlss-streamline\` (DLLs directly inside that directory, no subfolders), or point to another location with `pnpm run payload -- <dir>`. The build exits if they cannot be found.
- **ReShade_Setup_*_Addon.exe (optional)**: the payload first looks in `vendor\reshade-setup\` and uses it if found; otherwise it automatically downloads the **pinned 6.8.0** build (same version as the bundled SDK headers, SHA-256 verified, cached in `vendor\component-cache\`). If you manually place a different version, it must match the SDK version in `vendor\toolchain\reshade\`, otherwise the overlay ABI may misalign.
- **Optional extra overlay add-ons (optional)**: to bundle additional `.addon64` files, put them in `vendor\addons\` (each in its own first-level subdirectory). Usually left empty.

### 3. Network Configuration (Optional)

- **Temporary proxy for Node** (the payload step downloads Feeder/RenoDX and other components via Node fetch; Node does not use the system proxy by default):

```powershell
# Replace with your proxy port
$env:HTTPS_PROXY = 'http://192.168.2.4:7890'
# Native switch on Node 24+
$env:NODE_USE_ENV_PROXY = '1'
```

- **Temporary mirrors for Electron** (Electron and electron-builder binaries are downloaded from GitHub by default):

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_BUILDER_BINARIES_MIRROR = 'https://npmmirror.com/mirrors/electron-builder-binaries/'
```

`Note: these settings are session-scoped environment variables that vanish when the terminal closes; they do not affect system-wide configuration.`

### 4. Local Development

**Run the full test suite**

```powershell
pnpm test
```

Start the app

```powershell
pnpm start
```

### 5. Building & Packaging

Run in an **Administrator PowerShell**, in order:

```powershell
# 1. Install dependencies
pnpm install
# 2. Generate application icons
pnpm run icon
# 3. Prepare overlay build materials
pnpm run overlay:prepare
# 4. Compile the overlay
pnpm run overlay:build
# 5. Build the installer + portable zip
pnpm run build
```

### Caveats

- **Move the artifacts out of the workspace before running them**: installers/portables generated under `dist\` may carry a low integrity label, and double-clicking the installer fails with `Error writing temporary file`. Copy the exe somewhere outside the project directory (e.g. Downloads) before running it.
- **All component versions are SHA-256 pinned**: download URLs and digests for Feeder/RenoDX/dgVoodoo etc. are pinned in `src\core\*-release.js` and `scripts\build\collect-payload.js`; the payload build verifies each one and cross-checks the component fingerprints compiled into the overlay (a mismatch aborts the build). When upgrading a component, update the pins and the overlay headers in sync.
- **Component download cache**: all downloads land in `vendor\component-cache\`; a matching digest passes instantly, and manually placing downloaded components there skips the network entirely. The overlay toolchain (zig, ReShade SDK headers) is generated by `overlay:prepare` into `vendor\toolchain\`, with versions pinned in a single place — `scripts\build\prepare-overlay.ps1`; the second run downloads nothing.
